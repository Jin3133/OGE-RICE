## 测试目标

测试用于证明各模块满足已确认的业务规则，而不仅是代码能够运行。弱标签实验指标和演示页面不能替代业务验收。

## 第一阶段测试范围

### 数据模型测试

- 缺少任务编号、分析时期、阶段、定额或管理单元时校验失败；
- 面积、定额和水量不能为负数；
- 单位必须属于明确支持范围；
- 结束日期不能早于开始日期；
- 反馈记录必须包含对象、原因、人员和时间；
- 子版本必须关联有效父版本。
- 灌区不能具有父节点，灌片必须直接挂在灌区下，自定义单元只能挂在灌区或灌片下；
- 管理单元层级不能形成循环；
- 新版本只能指向同一业务对象的较低版本；
- 同一管理单元、作物和阶段的定额分配有效时期不能重叠；

### 计算规则测试

- 平方米与亩换算正确；
- `W = A × M`计算正确；
- 多管理单元汇总与逐单元结果一致；
- 参数修正后仅更新受影响结果并生成新版本；
- 缺少适用定额时拒绝计算。
- 对象版本不存在时拒绝计算，不自动使用最新版本；
- 草稿、已替代或已撤回的输入版本不得参与新计算；
- 遥感成果必须覆盖全部任务管理单元且观测时期与任务重叠；
- 每个任务管理单元必须具有且仅具有一条适用定额分配；
- 计算结果必须保存全部输入对象版本和实际数值快照。

### 空间统计测试

空间统计将在第二阶段补充，包括投影、边界裁剪、NoData、有效观测比例、跨栅格和跨单元等场景。

## 通过标准

所有自动化测试通过，错误信息可理解，测试数据和运行命令可复现，测试结果与需求和设计文档一致。
