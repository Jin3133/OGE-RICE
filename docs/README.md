# 禾灌智析项目文档索引

本目录保存与代码同步维护的项目文档。Markdown 是文档的主版本；只有比赛提交、汇报或验收明确要求时，才从经过审查的 Markdown 版本导出 Word 或 PDF。

文档结构参考 [software-engineering-document](https://github.com/cuizhenjie/software-engineering-document) 的软件工程阶段划分，并根据本项目规模进行精简。参考模板保存在 `references/software-engineering-document`，不直接作为项目交付物。

## 文档维护规则

1. 一个模块开始开发前，先补齐相应需求和设计；开发完成时同步更新开发记录和测试结果。
2. 文档中的“已完成”必须有代码、测试、运行结果或数据文件作为证据。
3. 演示参数、弱标签和临时规则必须明确标注，不得写成正式业务结论。
4. 未确认事项集中列入“待确认事项”，不在代码中设置隐含默认值。
5. 需求或接口发生变化时，记录变更原因、影响范围和日期。

## 模块完成定义

一个模块只有同时满足以下条件，才可以标记为完成：

- 业务用途和适用边界已经写清；
- 输入、输出、单位和错误条件已经定义；
- 实现代码通过静态检查；
- 核心正常路径和异常路径具有自动化测试；
- 使用一份可追溯数据完成重复运行；
- 文档、示例和实际实现保持一致。
